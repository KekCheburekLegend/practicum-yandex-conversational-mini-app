# Data Explorer

## Задача мини-приложения
Дать пользователю таблицу и dashboard для загруженного учебного CSV/JSON с фильтрами, группировкой и what-if параметром. Пользователь должен видеть, как изменение параметра влияет на результат, и получать воспроизводимый итог, который можно вернуть в диалог без ручного пересчёта.

## UX-примечания (где это живёт в интерфейсе)
- What-if параметр — компактный контрол рядом с таблицей; должен явно показывать, что данные не изменены, а только пересчитаны.
- Фильтры и группировка — в отдельной панели, скрытой по умолчанию; не должны постоянно занимать место на главном экране.
- Inspect-панель — только по кнопке Inspect, скрыта по умолчанию.
- Confirmation gate — только на экспорт и массовое изменение, а не на каждый фильтр.
- Воспроизводимость — индикатор версии состояния в компактном виде, без превращения экрана в debug-консоль.

## Открытые вопросы
- Нужна ли поддержка нескольких файлов одновременно в MVP или один файл на сессию?
- Нужен ли экспорт в CSV/JSON в MVP или это stretch?

## Границы MVP и предлагаемые решения

Ниже — аналитическое предложение для согласования, а не описание уже реализованных возможностей. Для первого вертикального среза предлагается **один учебный файл на сессию**, CSV с заголовками либо JSON как массив объектов. Экспорт и массовое изменение исходных данных предлагается оставить за пределами первого среза до решения команды. Если эти операции включат в MVP, они должны проходить через общий confirmation gate и audit trail. Фильтрация, группировка и what-if не должны менять исходный файл и не требуют подтверждения.

Допустимые размеры файла, число строк и колонок, кодировка, разделитель CSV и формат чисел должны быть явно согласованы и проверяться до обработки. Невалидные файлы, повторяющиеся или пустые имена колонок, несовпадающая структура строк и неподдерживаемые вложенные значения должны приводить к понятной ошибке; файл не исполняется как код. Правила определения типов, пустых значений и отображения ошибок должны быть едины при первоначальной загрузке и восстановлении сессии.

## Сценарий пользователя

1. Пользователь загружает файл вместе с запросом в Chat Shell и открывает карточку Data Explorer; при неоднозначной маршрутизации может выбрать приложение вручную.
2. Система проверяет файл и показывает таблицу, подходящие типам колонок агрегаты и dashboard. При ошибке объясняет, что исправить, и не создаёт некорректный результат.
3. Пользователь настраивает фильтры и группировку в панели и меняет what-if. Таблица и dashboard обновляются; интерфейс показывает, что исходный файл не изменён.
4. Runtime сохраняет конфигурацию и её версию. При повторном открытии той же версии система использует тот же исходный набор и правила вычисления.
5. Пользователь возвращает в чат итог: идентификатор сессии и версию состояния, характеристики набора, фильтры, группировку, what-if и рассчитанные агрегаты.

## Контракт данных: предложение для обсуждения

| Объект | Содержимое |
| --- | --- |
| Вход | Ссылка на сохранённую версию файла, его формат и метаданные; идентификатор сессии и версия приложения. |
| Состояние | Ссылка на исходный набор и его хэш, версия алгоритма/схемы, список фильтров с колонкой, оператором и значением, группировка и параметры what-if. |
| What-if | Числовая колонка и явно отображаемая операция с параметром; исходные данные сохраняются без изменений. Доступные операции и ограничения параметра согласовать с командой. |
| Выход | Сессия, версия состояния, выбранные настройки, число строк и ключевые агрегаты; при группировке — агрегаты по группам. |

Хэш проверяет идентичность данных, но сам по себе не позволяет восстановить файл: для воспроизводимости исходный набор должен оставаться доступным в течение согласованного срока. Фильтры предлагается применять к исходным значениям, затем к отобранным строкам применять what-if и рассчитывать агрегаты. Семантику округления, отсутствующих значений и типов колонок следует зафиксировать до реализации, чтобы повторный запуск давал одинаковый результат.

## Критерии приёмки Data Explorer

| Сценарий | Ожидаемый результат |
| --- | --- |
| Валидный CSV и валидный JSON | Приложение открывается из Chat Shell и показывает таблицу и dashboard на разрешённых примитивах. |
| Повреждённый или неподдерживаемый файл | Понятная ошибка; построение dashboard и исполнение содержимого файла не происходят. |
| Фильтр и группировка | Отображаемые строки и агрегаты соответствуют выбранным условиям; пустой результат отображается понятно. |
| What-if | Отображаемые агрегаты пересчитаны с указанным параметром, исходный набор не изменён. |
| Восстановление версии | Те же данные, версия алгоритма и конфигурация дают тот же итог; пользовательские правки и версия не теряются при возврате в чат. |
| Параллельное изменение | Устаревшая версия не перезаписывает более новую незаметно; пользователь получает сообщение о конфликте. |
| Критическое действие, если поддержано | До подтверждения операция не выполняется; решение и результат фиксируются в audit trail, отмена не меняет данные. |

**Пример для фикстуры:** строки `(книги, 100)`, `(курсы, 200)`, `(книги, 300)`. Фильтр по книгам даёт 2 строки и исходную сумму 400; what-if «умножить сумму каждой строки на 1,1» даёт 440, при этом файл остаётся прежним. Результат должен включать фильтр, параметр 1,1 и версию состояния. Числовой формат и округление в самой реализации требуют отдельного согласования.
