# Conversational Mini-App Studio

## Кратко

Собственная платформа, которая превращает запрос в чате не только в текст, но и в интерактивный, проверяемый интерфейс: доску исследования, план проекта или исследователь данных. Маршрутизатор выбирает инструмент, runtime открывает подходящее mini-app, а пользователь меняет параметры, видит источники и возвращает структурированный результат в диалог.

## Проблема и пользователи

Обычный чат плохо подходит для задач, где нужно сопоставлять доказательства, двигать сроки, фильтровать данные и проверять варианты. Студентам, исследователям и проектным командам нужен единый разговорный вход в специализированные визуальные рабочие пространства, где ответ можно исследовать, изменить и проверить, а не только прочитать.

## Цель

За два семестра создать расширяемую платформу с тремя обязательными mini-app, которая правильно выбирает приложение минимум для 90% эталонных запросов, отображает только валидные UI-схемы и сохраняет прослеживаемую цепочку «запрос → инструмент → данные → интерактивное действие → итог».

## Результат (продукт)

- собственная адаптивная chat shell;
- registry mini-app и инструментов;
- детерминированный tool router;
- runtime и renderer структурированных UI-схем;
- протокол передачи состояния между чатом, инструментом и mini-app;
- единый механизм подтверждения изменяющих операций и audit trail;
- evaluator для маршрутизации, схем, трасс и продуктовых сценариев;
- три обязательных приложения и два подготовленных stretch-модуля.

## Публичная граница интеграции

Этот проект по прямому решению заказчика находится вне трека Алисы и умного дома. Это **не ChatGPT App, не реализация OpenAI Apps SDK и не интеграция с ChatGPT или OpenAI**. Команда самостоятельно строит chat shell, registry, schemas, router, runtime и evaluator. Паттерн «диалог открывает насыщенное mini-app» используется только как референс взаимодействия, вдохновлённый классом GPT Apps.

Для MVP достаточно детерминированного маршрутизатора и schema renderer. Публичная или локальная языковая модель допустима как заменяемый эксперимент после готовности базовой платформы, но не требуется для приёмки, не определяет формат UI и не получает секреты внешних систем.

## MVP

### Обязательные mini-app

1. **Research Board** — визуальная доска источников, утверждений и противоречий; пользователь связывает claim с evidence и видит утверждения без источника.
2. **Project Planner** — timeline и dependency canvas; пользователь меняет длительность или зависимость и сразу видит критические конфликты и сдвиги.
3. **Data Explorer** — таблица и dashboard с фильтрами, группировкой и what-if параметром на загруженном учебном CSV/JSON.

### Stretch mini-app

4. **Decision Matrix** — совместное сравнение вариантов с весами критериев, чувствительностью результата и историей изменений.
5. **Learning Map** — преобразование загруженного учебного документа в карту понятий, карточки и проверяемый quiz с привязкой к фрагментам источника.

### Платформенный минимум

- текстовый чат, история и карточка запуска mini-app;
- manifest приложения: intents, входная/выходная schema, разрешённые actions и версия;
- минимум восемь переиспользуемых UI-примитивов renderer: текст, таблица, карточка, график, фильтр, форма, timeline/dependency edge и source link;
- state handoff «чат → mini-app → чат» без потери версии и пользовательских изменений;
- confirmation gate перед удалением, массовым изменением или экспортом;
- inspect-панель с выбранным route, tool arguments, schema validation и результатом;
- offline fixtures для всех обязательных приложений.

## Вне рамок

- публикация в ChatGPT, OpenAI, Yandex Dialogs или другом внешнем app-каталоге;
- универсальный автономный агент и бесконтрольная генерация исполняемого UI-кода;
- шесть production-grade приложений: обязательны три, ещё два — stretch;
- совместное редактирование в реальном времени в MVP;
- обработка конфиденциальных корпоративных документов;
- автоматический веб-поиск без отдельного разрешённого и цитируемого source adapter.

## Роли и вклад

- **Продакт/проект:** единая история продукта, приоритет сценариев, метрики и пилот.
- **Дизайн/UX:** chat-to-app переходы, UI schema primitives, inspectability и доступность.
- **Бэкенд/platform:** registry, router, runtime, state protocol, audit и evaluator.
- **Фронтенд:** chat shell, renderer, три обязательных mini-app и inspect-панель.
- **Data/AI:** эталонный корпус запросов, optional model adapter, оценка маршрутизации.
- **QA:** schema/property tests, состояние, подтверждения, миграции manifest и end-to-end сценарии.
- **Мобильная разработка:** не обязательна; адаптивный web входит в MVP.

## Этапы двух семестров

1. Исследование задач, единый product story, manifest и threat model.
2. Chat shell, registry, schema primitives и кликабельные прототипы трёх приложений.
3. Вертикальный срез: запрос → route → Research Board → изменение → результат в чат.
4. MVP runtime с Project Planner, Data Explorer, inspect-панелью и audit.
5. Evaluator, доступность, performance, пользовательский пилот; один stretch-app при запасе.
6. Документация SDK/manifest, галерея сценариев и живая защита.

## Риски и снижение

- **Проект превращается в набор несвязанных демо:** общий manifest, renderer, state protocol и evaluator обязательны раньше третьего приложения.
- **Генерируется небезопасный произвольный UI:** только allowlist schema primitives; HTML/JS из ответа не исполняется.
- **Маршрутизатор ошибается:** эталонный корпус, confidence threshold и безопасный выбор приложения пользователем.
- **Состояние теряется между чатом и app:** versioned state envelope, журнал событий и тесты round-trip.
- **Платформу принимают за ChatGPT App:** независимое название, брендинг и явный дисклеймер в продукте и README.
- **Scope пяти приложений слишком велик:** три обязательных приложения используют общие примитивы; Decision Matrix и Learning Map остаются stretch.

## Критерии приёмки

- Chat shell запускает Research Board, Project Planner и Data Explorer через единый registry/runtime; приложения не являются отдельными несвязанными страницами.
- На размеченном наборе минимум из 90 запросов не менее 90% маршрутизируются в ожидаемый инструмент или приложение; неизвестный запрос не запускает изменяющую операцию.
- Renderer принимает только versioned schema и отклоняет неизвестный компонент или невалидные props без исполнения произвольного кода.
- Все три приложения проходят по два end-to-end сценария, включая изменение пользователем и возврат структурированного итога в чат.
- Project Planner пересчитывает минимум три размеченных конфликта зависимостей, Data Explorer воспроизводимо применяет фильтр и what-if, Research Board выявляет утверждение без evidence.
- Удаление, массовое изменение и экспорт требуют подтверждения и отражаются в audit trail.
- Evaluator формирует отчёт по routing accuracy, schema validity, state round-trip и шести продуктовым сценариям.
- Интерфейс и README прямо заявляют отсутствие обязательной или официальной интеграции с ChatGPT/OpenAI.

## Оценивание

Платформенная архитектура и расширяемость — 25%; качество трёх mini-app — 25%; UX и inspectability — 20%; evaluator и тесты — 20%; безопасность и документация — 10%.
