# Data Explorer: серверный модуль

Модуль реализует загрузку одного учебного CSV или JSON на сессию, проверку, начальную UI-схему, сохранение версий конфигурации и структурированный итог для передачи в чат. Интерактивный интерфейс и пересчёт в браузере относятся к отдельной задаче фронтенда.

## Запуск

Требуется Python 3.11+. Из корня репозитория:

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements-dev.txt
python -m uvicorn explorer.app:app --host 127.0.0.1 --port 8000
```

Документация API доступна на `http://127.0.0.1:8000/docs`. Тесты: `python -m pytest -q`. Переменная `EXPLORER_DB` задаёт путь к файлу SQLite; по умолчанию используется `explorer.db` в текущей директории. Папка для файла БД должна существовать.

## Загрузка и форматы

`POST /api/data-explorer/sessions?filename=sales.csv` принимает **сырые байты файла** в теле запроса, а не multipart-форму. Пример с учебной фикстурой:

```powershell
curl.exe -X POST "http://127.0.0.1:8000/api/data-explorer/sessions?filename=sales.csv" --data-binary "@fixtures/data-explorer/sales.csv" -H "Content-Type: application/octet-stream"
```

- UTF-8, необязательный BOM; CSV с запятой и заголовками или JSON-массив объектов с одинаковыми полями.
- Не более 1 000 000 байт, 5000 строк и 50 колонок; имена от 1 до 100 символов без пробелов по краям, значения строк до 10 000 символов. Вложенные значения и повторные имена отклоняются.
- CSV: пустое поле превращается в `null`; канонические числа без пробелов преобразуются в числа, идентификаторы с ведущими нулями остаются строками. JSON сохраняет типы скалярных значений. Целые числа ограничены безопасным диапазоном JavaScript (`±(2^53−1)`), NaN и бесконечности запрещены.
- Некорректный файл возвращает `422`, файл сверх лимита — `413`. Исходные байты сохраняются без изменений, хэш SHA-256 вычисляется по ним.

## Работа с состоянием

Создание и чтение возвращают `state` (versioned state envelope), `data` (валидированные колонки и строки) и `ui_schema`. В `state.payload` находятся идентификация исходного файла и версия алгоритма, конфигурация и агрегаты.

| Запрос | Назначение |
| --- | --- |
| `GET /api/data-explorer/sessions/{id}` | Последняя версия. `?version=1` возвращает сохранённую предыдущую версию. |
| `PUT /api/data-explorer/sessions/{id}` | Сохранить конфигурацию с `expected_version`; устаревшая версия возвращает `409` без перезаписи. |
| `GET /api/data-explorer/sessions/{id}/handoff?version=2` | Вернуть только envelope и структурированный итог указанной версии для передачи общему runtime. |

Пример тела `PUT`:

```json
{
  "expected_version": 1,
  "configuration": {
    "filters": [{"column": "category", "operator": "eq", "value": "книги"}],
    "group_by": "category",
    "what_if": {"column": "amount", "operation": "multiply", "value": 1.1}
  }
}
```

Поддерживаются фильтры `eq`, `contains` (без учёта регистра), `gte`, `lte`. Числовые сравнения и what-if требуют числовой колонки; `contains` — строковой. Фильтры применяются к исходным значениям, затем выполняются what-if и группировка. Значения `null` не участвуют в суммах, количество включает все прошедшие фильтр строки. Сервер возвращает количество, суммы и группы; суммы округляются до шести знаков после запятой. Приложение принимает необязательное поле `client_aggregates`, но не доверяет ему: для сохранённого итога агрегаты вычисляются на сервере из исходных данных и конфигурации. Браузер и сервер должны использовать согласованные правила и тестовые примеры.

## Границы интеграции

- Ветка содержит локальный SQLite-адаптер, чтобы проверять сохранение, восстановление и конфликты до готовности общей БД. Он **не** заменяет PostgreSQL, SQLAlchemy и миграции из отдельных задач команды.
- `ui_schema` следует предварительному контракту с `schema_version`, `app_id`, `nodes` и шестью разрешёнными компонентами; его модель Pydantic проверяет типы и поля. Общая JSON Schema/Ajv-схема renderer ещё не утверждена, совместимость с ней предстоит проверить при интеграции.
- Handoff возвращает данные через API; запись в историю Chat Shell и общий Runtime по issue #22 ещё не подключены. Отсутствуют аутентификация, изоляция пользователей, политика хранения и защита от злоупотреблений: этот локальный сервер не предназначен для публичного развёртывания.
- Выгрузка исходного файла, экспорт и массовые изменения не реализованы. После изменения версии алгоритма или формата состояния необходима явная миграция: модуль откажет в изменении старой сессии, но сохранённые версии остаются доступны для чтения.
