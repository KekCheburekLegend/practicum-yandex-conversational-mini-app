# Project Planner

## Задача мини-приложения
Визуализировать график проекта, управлять зависимостями и автоматически находить конфликты в расписании. Пользователь должен наглядно видеть, как изменение одной задачи влияет на весь проект, и мгновенно получать обратную связь о критических сдвигах без ручного пересчета.

## Таблица требований

| Процедура | Выполняемые действия в рамках процедуры | Тип требования | Требование | Приоритет |
| --- | --- | --- | --- | --- |
| Составление расписаня | автоматичческиое составление расписания | бизнес-требование | Снизить нагрузку с человека при планировании расписания | высокая |
| Валидация расписания | Автоматическая проверка |  бизнес-требование | Уменьшить ошибки при составлении расписания | высокая |
| Запрос на составление или изменение расписания | Отправка текстового запроса (и при необходимости файла с задачами) в Chat Shell | Функциональное | Система должна корректно распознавать профильный запрос и запускать Project Planner внутри единого контейнера Chat Shell через карточку запуска | Высокий |
| Создание и отрисовка расписания | Получение структурированных данных из запроса, файла, валидация схемы и построение временной шкалы | Функциональное / Архитектурное | Приложение должно формировать и отображать интерактивный график задач и связей строго через разрешенные UI-примитивы без исполнения произвольного кода | Высокий |
| Редактирование расписания | Интерактивное изменение длительности задач, сдвиг сроков на шкале, добавление или удаление зависимостей между задачами | Функциональное | Пользователь должен иметь возможность вручную изменять длительность задач и связи между ними с сохранением актуальной версии состояния | Высокий |
| Пересчет сдвигов и поиск конфликтов | Автоматический пересчет сроков всех зависимых задач в реальном времени и проверка расписания на наличие нарушений | Функциональное | Приложение должно мгновенно пересчитывать сдвиги и визуально подсвечивать критические конфликты | Высокий |
| Подтверждение критических операций | Перехват команд на удаление задач, массовый сдвиг расписания или экспорт плана и запрос явного согласия пользователя | Функциональное | Удаление, массовое изменение или экспорт расписания должны блокироваться механизмом до подтверждения пользователем и фиксироваться в audit trail | Высокий |
| Возврат результата в диалог | Формирование структурированного итога (список изменений и оставшихся конфликтов) и передача его обратно в ленту чата | Функциональное | Протокол должен обеспечивать возврат обновленного плана из Project Planner в Chat Shell без потери пользовательских правок и версии состояния | Высокий |
