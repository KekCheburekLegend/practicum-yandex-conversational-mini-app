# Frontend — Chat Shell

Каркас интерфейса по задаче #15. React, TypeScript, Vite и CSS Modules.

## Запуск

Требуется Node.js 22.12+ или 24 LTS.

```sh
cd frontend
npm ci
npm run dev
```

Откройте адрес, который напечатает Vite. Проверка типов и production-сборка выполняются командой `npm run build`. Просмотр сборки — `npm run preview`.

## Возможности

- Создание и переключение диалогов, отправка сообщений кнопкой или Enter. Shift + Enter добавляет строку.
- Вкладки Research Board, Project Planner и Data Explorer в едином рабочем пространстве.
- Тёмная и светлая темы, выбор акцентного цвета, адаптивная компоновка.
- Явное обозначение демонстрационного режима и места подключения mini-app.

Состояние диалогов и оформления хранится в памяти вкладки. Перезагрузка сбрасывает его. Пользователь явно выбирает приложение, после отправки отображается демонстрационный ответ. Backend API, маршрутизатор и runtime подключаются в следующих задачах. Платформа самостоятельная, обязательная или официальная интеграция с ChatGPT/OpenAI отсутствует.

## Schema Renderer

`SchemaRenderer` принимает `schema: unknown`, `onAction` и необязательный `onInspect`. Ajv проверяет весь документ до отрисовки. Поддерживаемая версия — `schema_version: "1.0"`. Обязательны `app_id` и массив `nodes`. Каждый узел содержит `component_type`, `props`, а контейнеры card и form — ещё `nodes`. Формат определён в `src/renderer/schema.ts`. Это начальный frontend-контракт, который необходимо согласовать с registry/runtime.

Разрешены text, card, table, chart, filter, form, timeline и source-link. Неизвестные поля и компоненты отклоняются. Ссылки принимают абсолютные HTTP(S) URL без учётных данных. Текст экранируется React. Вход ограничен по глубине и размеру. Chart отображает неотрицательные значения. Form группирует дочерние элементы и отправляет действие кнопки, filter передаёт выбранное значение отдельным событием.

`onAction` передаёт `{ app_id, action, payload }` в вызывающий код. Действия остаются данными. Выполнение операций и подтверждения обеспечивает будущий runtime. `onInspect` получает `{ valid, errors: [{ path, message }] }` для состояния шага. В Chat Shell показаны примеры всех восьми компонентов. В Inspect можно вставить собственный JSON, проверить ошибки и посмотреть последнее действие. Демонстрационные данные и настройки Inspect сбрасываются при смене приложения.

Тесты выполняются командой `npm test`. Проверяются восемь примитивов, вложенность, неизвестные компоненты, версия, типы props, опасные URL, дополнительные поля и экранирование HTML.
